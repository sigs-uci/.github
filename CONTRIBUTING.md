# Help keep SIGS information accurate

We welcome reports of broken pages, accessibility barriers, and factual errors. For a public website issue, use the [website repository](https://github.com/sigs-uci/sigs-uci.github.io/issues) and check for an existing report first. For a problem with this GitHub profile, use [this repository's issues](https://github.com/sigs-uci/.github/issues).

You can write reports and corrections in English or Persian.

<p dir="rtl" lang="fa">می‌توانید گزارش مشکل یا اصلاح پیشنهادی را به فارسی یا انگلیسی بنویسید.</p>

Include the public page URL, what needs to change, and the result you expected. For a factual correction, explain the proposed wording and link a public source when one exists. An archived announcement is evidence of what was advertised, so a correction should not turn it into a claim that the event took place.

Use only information you are comfortable making public. Email [sigs@uci.edu](mailto:sigs@uci.edu) for a photo removal request, personal information, unpublished supporting material, or a concern about another person. Follow [SECURITY.md](SECURITY.md) for a security report.

Before proposing code or a content edit, read the destination repository's README and editing instructions. Keep the change focused and check its links. New event details, photographs, and translations need their publication review before they appear publicly. A correction does not grant permission to publish someone else's photograph or contact details.

Maintainers review changes and publish approved updates on `main`. Website deployment has a separate release step. Do not commit built output, dependencies, credentials, or private records.
